## 6. 예약·결제 사용자 흐름

| 단계 | 사용자 행동 | 시스템 처리 |
|---|---|---|
| 1 | 시술 + 옵션 선택 | 총 소요시간·금액 계산 |
| 2 | 디자이너 선택(또는 "상관없음") | 해당 시술 가능 디자이너 필터 |
| 3 | 날짜 선택 | 영업일·휴무·잔여 슬롯 기준 활성화 |
| 4 | 시간 선택 | 소요시간만큼 연속 슬롯 **10분 임시 홀드** |
| 5 | 정보 입력 + 휴대폰 인증 | 비회원 가능(휴대폰 기준 식별), 회원은 자동 입력 |
| 6 | 결제(예약금 or 선결제) + 취소규정 동의 | PG 결제창 → 서버 승인 검증(금액 위변조 체크) |
| 7 | 예약 확정 | 상태 `CONFIRMED`, 알림톡 발송, 캘린더 반영 |
| 8 | 전날·당일 리마인더 | 알림톡(전날 18시, 당일 2시간 전) |
| 9 | 방문·시술 → 잔금 현장 결제 | 관리자 `COMPLETED` 처리 → 적립금·후기 요청 |

- 예약 상태: `HOLD → PENDING_PAYMENT → CONFIRMED → COMPLETED / CANCELED / NO_SHOW`
- 홀드 만료·결제 실패 시 슬롯 자동 반환

### 리스크 및 체크포인트
- 예약 동시성(더블부킹) → DB 레벨 잠금·유니크 제약으로 방지
- 저작권 → 화이트리스트 소스만, 요약+링크 원칙, 삭제 요청 대응 프로세스
- 개인정보 → 최소 수집(이름·휴대폰), 알러지 정보는 민감정보 여부 검토·별도 동의
- 알림톡 템플릿 심사 기간(3~5영업일)을 일정에 반영
